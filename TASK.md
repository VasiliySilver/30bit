# Тестовое задание: мини‑сервис “Reading List” (Python / FastAPI / ORM)

## Коротко о задаче:
Сделать небольшой REST API сервис «Reading List»: пользователи ведут списки материалов (книги/статьи) с метками и статусами. Нужны простые CRUD‑операции и базовая фильтрация.

## Сущности (минимум)
User: id, email (уникальный), display_name, created_at;
Item: id, user_id, title, kind (book|article), status (planned|reading|done), priority (low|normal|high), notes (текст), created_at, updated_at;
Tag: id, user_id, name (уникальна в рамках пользователя);
M2M: Item—Tag.

Можно использовать любую SQL. Миграции приветствуются, но не обязательны.

# Требования к API (минимальный набор)
CRUD для Item: создать / получить по id / список / обновить / удалить;
Список Item с фильтрами: по status, kind, priority, тегам (любая из), подстрока в title, по диапазону дат created_at;
Пагинация (limit/offset) и сортировка (created_at|updated_at|priority, asc/desc);
Управление тегами: создать/список тегов; добавить/убрать теги у Item (можно одним запросом);
Ответы — JSON. Ошибки — JSON с сообщением и кодом.

# Нефункциональные ожидания
Структура проекта читаемая (routers/schemas/models/... — по вашему вкусу);
Конфигурация через переменные окружения;
README с инструкцией запуска (локально), примерами запросов, решениями/допущениями;
Набор seed‑данных: 2 пользователя, 5–8 Item с разными статусами/приоритетами и несколько тегов.

# Мини‑подсказки
Делайте минимально жизнеспособно, начните с чистого CRUD и фильтров;
Упрощения допустимы — главное, опишите их в README;
Чем ближе сервис будет к production решению, тем лучше.

# Что прислать
Исходники (ссылка на репозиторий или архив);
README (запуск, примеры запросов, решения/компромиссы);
Файл seed‑данных и способ его применить.
Критерии приёмки (минимум)
Сервис стартует локально и отвечает на заявленные эндпоинты;
CRUD Item, фильтры, пагинация, сортировка работают предсказуемо;
Теги создаются/привязываются/отвязываются.
